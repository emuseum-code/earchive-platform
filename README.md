# Архів: розпізнавання архівних документів

Адмінка для розпізнавання архівних справ: скани аркушів зі сховища → розпізнавання Gemini (поля опису документа й повний текст) → звірка зі сканом → AI-перевірка → описова стаття ISAD(G) → експорт.

Репозиторій emuseum-code/earchive-platform, домен arch.emuseum.ua. Копія системи eBooks (emuseum-code/books), перероблена під архівні документи. Стек: Laravel 13 + Filament 5, PHP 8.3, PostgreSQL (локально SQLite), черга Laravel (database).

## Швидкий старт

```bash
cd admin
composer install
cp .env.example .env
php artisan key:generate
touch database/database.sqlite
php artisan migrate --seed
php artisan filament:assets
php artisan serve                      # http://127.0.0.1:8000/admin
php artisan queue:work --queue=interactive,default   # окремо: розпізнавання, AI-перевірка, опис, експорт
php artisan schedule:work              # окремо: синхронізація за розкладом, відновлення черги
```

Демо-користувачі (пароль `password` або значення `ADMIN_PASSWORD` з `.env`):

| Логін | Роль | Що може |
|---|---|---|
| admin@archive.test | Адміністратор | усе, користувачі, налаштування, журнал |
| operator@archive.test | Оператор (+ опис і експорт) | синхронізація, справи, черга, розпізнавання, опис, експорт |
| verifier@archive.test | Верифікатор | звірка документів зі сканом, правки, зауваження, AI-перевірка |
| viewer@archive.test | Перегляд | лише перегляд справ, документів і сканів |

Демо-дані: Демонстраційний архів → Ф. Р-101 → оп. 1 → спр. 7 «Листування з окружною інспектурою народної освіти про ремонт школи», 4 аркуші, 4 документи (лист на двох аркушах, довідка, протокол, кошторис). **Документи вигадані, зображення згенеровані** (`tools/make_demo_case.py`).

## Як влаштовано

- Сховище: `Область/Архів/Фонд/Опис N/Справа` (правила рівнів папок — Налаштування → Сховище). Номер фонду, опису й справи береться з назв папок («Ф. Р-101 …», «Опис 1», «Справа 7 …»), архівний шифр справи — `Ф. Р-101, оп. 1, спр. 7`.
- Документ (рядок єдиної таблиці): № у справі, індекс, дата, аркуші, архівний шифр, вид, заголовок, короткий зміст, автор, адресат, місце складання, мова, справжність, спосіб відтворення, особи, географічні назви, установи, повний текст, фізичний стан, резолюції й печатки.
- Одна сторінка може мати кілька документів, а документ — кілька аркушів: продовження з попередньої сторінки дописується в повний текст того самого документа.
- Шаблон розпізнавання «Архівний документ (універсальний)»: промпт і поля редагуються в адмінці (Розпізнавання → Шаблони).
- Опис ISAD(G): схема, довідники (види документів, мови, справжність, спосіб відтворення, стан) і правила відповідностей — Адаптація й експорт.

## Gemini

Ключ тільки в `.env`: `GEMINI_API_KEY=...`. Без ключа працює демо-режим: розпізнавання повертає попередній результат, AI-перевірка пропонує значення із зауважень верифікатора. Модель, ліміти запитів, місячний бюджет і промпти задаються в адмінці: Адміністрування → Налаштування → Gemini AI.

## Що де

- `admin/app/Services/`: `StorageSync` (обхід сховища за правилами папок), `GeminiClient`, `RecognitionService`, `AiCheckService`, `AdaptationService`, `ExportService`, `QueueManager`.
- `admin/app/Jobs/RunProcessingJob.php`: виконання завдань черги (пауза, ліміт, повтори з відступом, бюджет).
- `admin/app/Filament/`: ресурси, сторінки «Налаштування», «Дерево сканів», екран звірки `Records/Pages/ReviewRecord`.
- `admin/database/migrations/`: усі таблиці (структура → документи → архівний опис).
- `admin/database/seeders/RegistrySeeder.php`: схема опису ISAD(G), довідники, правила відповідностей.
- Команди: `php artisan archive:sync {path?} {--checksum}`, `php artisan archive:recover`.

## Ролі та права

Доступ описано в `App\Filament\Support\Access`: кожен ресурс задає `viewAccess()` / `editAccess()` (`all`, `staff`, `operate`, `verify`, `adapt`, `admin`). Оператор і верифікатор бачать лише призначені їм архіви або справи (якщо призначення є).

Суміщення ролей (лише адміністратор, у картці користувача): оператору можна додати звірку (`can_verify`), верифікатору обробку (`can_operate`). Право на адаптацію й експорт (`can_adapt_export`) дається окремо.

## Звірка

Екран `/admin/records/{id}/review`: скан ліворуч лишається на екрані під час прокручування полів.

- Олівець (✎ біля поля або над сканом): обвести на скані місце з помилкою, виділити мишею в полі текст, що не збігається, і натиснути «Зберегти й перевірити AI». Фрагмент зберігається в `review_remarks.fragment` і передається в AI-перевірку як `mismatched_text`; на скані й під полем він підсвічується тим самим номером.
- Гарячі клавіші: Ctrl/⌘+S зберегти, Ctrl/⌘+Enter підтвердити звірку, Alt+PgDn/PgUp наступний/попередній документ, Alt+←/→ сторінки скану.
- Глобальний пошук (Ctrl/⌘+K): документи за номером, індексом, архівним шифром і заголовком, справи за назвою й папкою.

## Завантаження сканів з браузера

Справи → «Нова справа зі сканів» (архів, фонд, назва, файли) або в картці справи «Завантажити скани». Файли лягають у папку справи в кореневій директорії й одразу реєструються як сторінки цієї справи, без синхронізації: сховище не обходиться, інші папки не перевіряються, у журналі синхронізацій документ не з’являється. JPG і PNG браузер зменшує ще до відправлення до `storage.upload_max_px` по довшій стороні (Налаштування → Сховище, типово 3000 px; 0 — завантажувати оригінали). Реєструються лише розширення з налаштування «Розширення файлів». Порядок сторінок: «обложка…» перша й не розпізнається, «посл.стр…» остання, решта в природному порядку назв (IMG_0001, IMG_0002…), бо камери не пишуть у назви ні архів, ні номер сторінки.

Сховище на сервері: `storage/app/scans` (постійний том). Команда `archive:storage-init` при кожному деплої копіює туди демо-скани. Якщо коренева директорія задана вручну, команда її не змінює.

Швидкий вхід: на сторінці логіну кнопки демо-користувачів. Вимкнути: `DEMO_QUICK_LOGIN=false` у `.env`.

## Масова обробка

Поки адміністратор не ввімкне «Масову обробку дозволено» (Налаштування → Gemini AI), за один запуск розпізнавання можна взяти не більше `ai.test_scan_limit` сторінок (типово 100). Так спершу проганяють тестову партію й перевіряють якість і вартість.

## Резервні копії

Сервіс `archive-backup` (`deploy/backup.sh`, образ postgres:16-alpine) щодня о `BACKUP_HOUR` (01 UTC) робить `pg_dump -Fc` у том `backups`, зберігає 14 днів і регулярно перевіряє відновлення в тимчасову базу `archive_restore_check`.

## Деплой

Лише вручну: Actions → Deploy → Run workflow, після узгодження з координатором (VPS спільний). Образ збирається на Actions, `docker save` → ssh → `docker load` на VPS (`/opt/archive`, compose-проєкт `archive`, усі сервіси в мережі `mincult_default`), сайт Caddy `/opt/caddy-sites/archive.caddy` перевіряється `caddy validate` перед перезавантаженням. Секрети тільки в GitHub Secrets (DEPLOY_SSH_KEY, DEPLOY_HOST, DEPLOY_USER, DOMAIN, ADMIN_PASSWORD, за потреби GEMINI_API_KEY). Пароль демо-користувачів `*@archive.test` синхронізується з ADMIN_PASSWORD при кожному деплої.
