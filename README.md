# Архів: розпізнавання архівних документів

Адмінка системи обліку та розпізнавання архівних облікових (інвентарних) справ: скани справ зі сховища → розпізнавання Gemini → звірка зі сканом → AI-перевірка → адаптація до шаблону РМФУ → експорт.

Стек: Laravel 13 + Filament 5, PHP 8.3, PostgreSQL (локально SQLite), черга Laravel (database).

## Швидкий старт

```bash
cd admin
composer install
cp .env.example .env
php artisan key:generate
touch database/database.sqlite
php artisan migrate --seed
php artisan filament:assets
php artisan serve                      # http://127.0.0.1:8000/admin
php artisan queue:work --queue=interactive,default   # окремо: розпізнавання, AI-перевірка, адаптація, експорт
php artisan schedule:work              # окремо: синхронізація за розкладом, відновлення черги
```

Демо-користувачі (пароль `password` або значення `ADMIN_PASSWORD` з `.env`):

| Логін | Роль | Що може |
|---|---|---|
| admin@books.test | Адміністратор | усе, користувачі, налаштування, журнал |
| operator@books.test | Оператор (+ адаптація й експорт) | синхронізація, справи, черга, розпізнавання, адаптація, експорт |
| verifier@books.test | Верифікатор | звірка документів зі сканом, правки, зауваження, AI-перевірка |
| viewer@books.test | Перегляд | лише перегляд справ, документів і сканів |

Демо-дані: Лисичанський краєзнавчий архів → Документальний фонд (Д) → «Справа Д-ІІІ (документи)», 4 розвороти, документи № 1685–1819 з прикладу `Справа архіву розпізнаний текст.xlsx`, адаптації до РМФУ і пробний експорт. **Зображення розворотів згенеровані** з розпізнаного тексту (`tools/make_demo_scans.py`), це не фото справжньої справи.

## Gemini

Ключ тільки в `.env`: `GEMINI_API_KEY=...`. Без ключа працює демо-режим: розпізнавання повертає попередній результат, AI-перевірка пропонує значення із зауважень верифікатора. Модель, ліміти запитів, місячний бюджет і промпти задаються в адмінці: Адміністрування → Налаштування → Gemini AI.

## Що де

- `admin/app/Services/`: `StorageSync` (обхід сховища за правилами папок), `GeminiClient`, `RecognitionService`, `AiCheckService`, `AdaptationService`, `ExportService`, `QueueManager`.
- `admin/app/Jobs/RunProcessingJob.php`: виконання завдань черги (пауза, ліміт, повтори з відступом, бюджет).
- `admin/app/Filament/`: ресурси, сторінки «Налаштування», «Дерево сканів», екран звірки `Records/Pages/ReviewRecord`.
- `admin/database/migrations/`: усі таблиці (структура → документи → реєстр РМФУ).
- `admin/database/seeders/RegistrySeeder.php`: шаблон міграції РМФУ (42 поля), довідники, правила адаптації.
- Команди: `php artisan books:sync {path?} {--checksum}`, `php artisan books:recover`.

## Ролі та права

Доступ описано в `App\Filament\Support\Access`: кожен ресурс задає `viewAccess()` / `editAccess()` (`all`, `staff`, `operate`, `verify`, `adapt`, `admin`). Оператор і верифікатор бачать лише призначені їм архіви або справи (якщо призначення є).

Суміщення ролей (лише адміністратор, у картці користувача): оператору можна додати звірку (`can_verify`), верифікатору обробку (`can_operate`). Право на адаптацію й експорт (`can_adapt_export`) дається окремо.

## Звірка

Екран `/admin/records/{id}/review`: скан ліворуч лишається на екрані під час прокручування полів.

- Олівець (✎ біля поля або над сканом): обвести на скані місце з помилкою, виділити мишею в полі текст, що не збігається, і натиснути «Зберегти й перевірити AI». Фрагмент зберігається в `review_remarks.fragment` і передається в AI-перевірку як `mismatched_text`; на скані й під полем він підсвічується тим самим номером.
- Гарячі клавіші: Ctrl/⌘+S зберегти, Ctrl/⌘+Enter підтвердити звірку, Alt+PgDn/PgUp наступний/попередній документ, Alt+←/→ сторінки скану.
- Глобальний пошук (Ctrl/⌘+K): документи за номером, обліковим та інвентарним номером, справи за назвою й папкою.

## Завантаження сканів з браузера

Справи → «Нова справа зі сканів» (архів, фонд, назва, файли) або в картці справи «Завантажити скани». Файли лягають у папку справи в кореневій директорії й одразу реєструються як сторінки цієї справи, без синхронізації: сховище не обходиться, інші папки не перевіряються, у журналі синхронізацій документ не з’являється. JPG і PNG браузер зменшує ще до відправлення до `storage.upload_max_px` по довшій стороні (Налаштування → Сховище, типово 3000 px; 0 — завантажувати оригінали). Реєструються лише розширення з налаштування «Розширення файлів». Порядок сторінок: «обложка…» перша й не розпізнається, «посл.стр…» остання, решта в природному порядку назв (IMG_0001, IMG_0002…), бо камери не пишуть у назви ні архів, ні номер сторінки.

Сховище на сервері: `storage/app/scans` (постійний том). Команда `books:storage-init` при кожному деплої копіює туди демо-скани й зразки (`storage/sample-scans`: 4 реальні розвороти Лисичанського архіву) і створює групи збереження архіву з переліку Мінкульту. Якщо коренева директорія задана вручну, команда її не змінює.

Швидкий вхід: на сторінці логіну кнопки демо-користувачів. Вимкнути: `DEMO_QUICK_LOGIN=false` у `.env`.

## Масова обробка

Поки адміністратор не ввімкне «Масову обробку дозволено» (Налаштування → Gemini AI), за один запуск розпізнавання можна взяти не більше `ai.test_scan_limit` сторінок (типово 100: стільки сторінок Мінкульт дає на перше калібрування). Так спершу проганяють тестову партію й перевіряють якість і вартість.

## Резервні копії

Сервіс `books-backup` (`deploy/backup.sh`, образ postgres:16-alpine) щодня о `BACKUP_HOUR` (01 UTC) робить `pg_dump -Fc` у том `backups`, зберігає 14 днів. Щонеділі й при першому запуску копія повністю відновлюється в тимчасову базу `books_restore_check` і перевіряється кількість користувачів і документів; в інші дні перевіряється зміст архіву. Стан пишеться в `last.json`, адміністратор бачить його на Огляді й у Налаштування → Резервні копії.

Зробити копію зараз: `docker compose -p books exec books-backup sh /backup.sh now`.
Відновити (спершу зупинити books-app, -queue, -scheduler): `docker compose -p books exec books-backup sh -c 'PGPASSWORD=$POSTGRES_PASSWORD pg_restore -h books-db -U books -d books --clean --if-exists /backups/books-YYYYMMDD-HHMM.dump'`.

## Деплой

Push у `main` запускає GitHub Actions: образ збирається на Actions, `docker save` → ssh → `docker load` на VPS (`/opt/books`, compose-проєкт `books`), сайт Caddy `/opt/caddy-sites/books.caddy` перевіряється `caddy validate` перед перезавантаженням. Секрети тільки в GitHub Secrets (DEPLOY_SSH_KEY, DEPLOY_HOST, DEPLOY_USER, DOMAIN, ADMIN_PASSWORD, за потреби GEMINI_API_KEY). Пароль демо-користувачів `*@books.test` синхронізується з ADMIN_PASSWORD при кожному деплої.
